Posts Scheduler Feature Status

This document provides a comprehensive overview of the newly integrated Posts Scheduler feature, detailing its current architecture, capabilities, and a roadmap of what remains to be done to make it fully production-ready for scale.

🌟 Current Capabilities (What's Done)

The foundation of the auto-posting system is complete and functional for basic usage.

1. Database Architecture

  • scheduled_posts Table: Tracks all posts with their target network (Facebook/Instagram), captions, media references, scheduled times, and their current lifecycle status (PENDING, PUBLISHED, FAILED).
  • media_uploads Table: A robust storage system that saves raw media binaries (images/videos) directly inside PostgreSQL.
  • Optimized Queries: An index on (status, scheduled_time) ensures the cron job can instantly find posts due for publication.

2. Backend API & Uploads Streamer

  • Base64 JSON Uploads: The /api/upload endpoint receives files from the dashboard encoded in Base64 and stores them in the database.
  • Media Streaming Edge: The /api/uploads/:id endpoint publicly streams the binary files back to the internet. This acts as a proxy so that Meta's Graph API can download your media during the publishing phase.
  • Publishing Pipeline (/api/cron/publish): Secured via a CRON_SECRET, this endpoint finds due posts, locks them to prevent double-publishing, sends them to Meta, and records the resulting Post IDs.

3. Meta Graph API Integrations

  • Facebook Feed: Native support for publishing text, images, and videos to Facebook Pages.
  • Instagram Containers: Full implementation of Meta's asynchronous 2-step media container publishing.
  • Race Condition Safety: Built-in retry loops that prevent the dreaded Code 9007 (Media ID not available) and Code 100 errors by waiting for Meta's servers to finish processing the media before forcing the publish command.
  • Never-Expiring Tokens: The system automatically exchanges your tokens with Meta to ensure they never expire, guaranteeing your cron jobs don't suddenly fail months from now.

4. Dashboard User Interface

  • Unified Posts Tab: A clean, modern interface (posts.js) that lets you view pending posts, retry failed ones, and delete them.
  • Live Feed Integration: You can view active, already-published posts directly inside the dashboard.
  • Interactive Picker: The Campaigns tab now allows you to visually select an active post to bind your auto-reply bots to, rather than copying and pasting IDs.

🚧 What's Left to Do (Roadmap)

While the feature works, it currently faces strict infrastructure limitations (specifically regarding Vercel's free tier) and lacks advanced social media capabilities. Here is the action plan:

1. Bypass Vercel's Cron Limitations

⚠️ The Issue: Vercel's Free tier limits cron jobs to running once per day. A real post scheduler needs to check for due posts every minute.

The Fix: We need to set up a third-party, free cron service (like cron-job.org or Upstash) to send a secure POST request to https://your-app.vercel.app/api/cron/publish every 1 minute.

2. Fix Large Video Uploads (The 4.5MB Limit)

⚠️ The Issue: We are currently uploading files via Base64 JSON strings. Vercel's serverless functions strictly block request bodies larger than 4.5MB, meaning large video uploads will crash the dashboard.

The Fix: We must transition away from Base64 JSON. Instead, we should implement direct multipart/form-data uploads, or better yet, upload files directly from the browser to Supabase Storage Buckets, completely bypassing Vercel's payload limits.

3. Support Instagram Carousels

ℹ️ Note: Currently, the system only supports scheduling a single image or video per post.

The Fix: Update the dashboard UI to accept multiple files in the drag-and-drop zone. Update the database schema to store an array of media IDs. Update the Instagram API integration to generate an ITEM container for each media file, followed by a CAROUSEL container to group them together before publishing.

4. Timezone Accuracy & Handling

ℹ️ Important: When a user selects "4:00 PM" in the dashboard, we must ensure it translates flawlessly to the UTC time stored in the database, accounting for Daylight Saving Time.

The Fix: Add a visual timezone indicator in the scheduler UI (e.g., "Scheduling in GMT+3"). Ensure the frontend explicitly passes ISO-8601 UTC timestamps to the backend.

5. Post Editing Capabilities

ℹ️ Note: Currently, if you make a typo in a scheduled post, you have to delete it and recreate it.

The Fix: Add an "Edit" button to the pending queue in the dashboard. This requires a new PUT /api/posts/schedule/:id endpoint to safely modify the text, media, or scheduled time without breaking the lock mechanisms.

6. Analytics and Insights

ℹ️ Tip: After a scheduled post goes live, users want to know how it's performing.

The Fix: Extend the Live Feed tab to display real-time Like and Comment counts fetched via the Graph API, providing a complete end-to-end publishing and tracking experience.
