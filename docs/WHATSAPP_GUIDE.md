# WhatsApp — setup and operations guide

The WhatsApp counterpart of [`TOKEN_GUIDE.md`](TOKEN_GUIDE.md) and [`TIKTOK_GUIDE.md`](TIKTOK_GUIDE.md). Everything
needed to connect a WhatsApp number, keep it healthy, test it, take it live, and add a managed customer's number.

Claims about the app name the file or route so you can check them (checked against `main` on 2026-10-25). Claims about
Meta's dashboards come from the owner's own setup on **2026-10-19** and say so — Meta moves its UI around, so treat those
as "what it looked like then". The design spec behind all of this is kept outside this public repo. Every hop a WhatsApp
message takes: [`FLOWS.md`](../FLOWS.md) §10.

## 1. One-time Meta setup (about 20 minutes)

### 1.1 Add WhatsApp to the existing app

developers.facebook.com → **My Apps** → **AutoResponseBot** → **Add use cases** (top right of the app Dashboard) →
**Connect with customers through WhatsApp** (shown later in the use-case switcher as "Connect on WhatsApp").

Use the same app, not a new one: the webhook's signature check uses this app's secret (`META_APP_SECRET`), so a second
app would need a second secret in `src/utils/signature.ts`. A use case cannot be removed once added.

### 1.2 Claim the free test number

Use case **Connect on WhatsApp** → **Step 1. Try it out** → **Claim a WhatsApp test number**. Meta shows:

- the **test number** (a `+1 555 …` number),
- its **Phone Number ID**,
- the **WhatsApp Business account ID**.

Under **Send a message from your test number → To**, add **your own WhatsApp phone** and enter the code WhatsApp sends
you. A test number can only talk to recipients added here — that is why it is safe to build on.

Ignore "Access token — Not generated yet" on this page: that is a 24-hour token. Make the permanent one in §1.4.

### 1.3 Point the webhook at the app

Use case **Connect on WhatsApp** → **Step 2. Production setup** → **Configure Webhooks** (also reachable as the
use case's **Webhooks** page):

1. **Callback URL**: `https://msg-response-auto.vercel.app/webhook`
2. **Verify token**: copy it from the dashboard → **Settings → Advanced → Webhook verify token**, while in the **Default** workspace (§8 explains
   why the workspace matters). Paste it into Meta — never into chat.
3. **Verify and save** (it stays greyed out while the token box is empty).
4. Leave **Attach a client certificate** off. Do **not** click **Remove subscription**.
5. **Webhook fields** (same page, below): subscribe exactly these seven, all at the version Meta pre-selects (`v26.0`):

   | Field | Why |
   |---|---|
   | `messages` | incoming messages **and** delivery statuses of what we send |
   | `account_update` | restrictions, policy events, disconnections |
   | `account_alerts` | Meta's alerts about the account |
   | `phone_number_quality_update` | quality rating changes (green / yellow / red) |
   | `phone_number_name_update` | display-name review results |
   | `business_capability_update` | messaging-limit changes |
   | `user_preferences` | a customer stopping (or resuming) marketing messages |

Leave the rest unsubscribed (calls, groups, flows, templates, `smb_*`/coexistence fields belong to later phases).

**What "verified" looks like from our side** (logs, `vercel logs msg-response-auto.vercel.app --since 30m`):
`GET /webhook` followed by `webhook.verified`. The handshake lives at `src/index.ts:322`.

### 1.4 Create the permanent token (system user)

This is in **Business Settings**, not in the developer dashboard:

1. business.facebook.com/settings/system-users (or business.facebook.com → ⚙️ **Settings** → **Users → System
   users**). Check the business in the top-left is the one that owns the app.
2. **Add** → a name like `autoreply-whatsapp` → role **Admin** → **Create**.
3. With the system user selected, **Assign assets**:
   - **Apps** → **AutoResponseBot** → **Full control** → Save
   - **WhatsApp accounts** → the account from §1.2 → **Full control** → Save
4. **Generate token** → app **AutoResponseBot** → expiration **Never** → permissions
   `whatsapp_business_messaging`, `whatsapp_business_management`, `business_management` → **Generate**.
5. Copy it into your password manager. Meta shows it once.

Snags met on 2026-10-19:

| What you see | Cause | Fix |
|---|---|---|
| "**No permissions available** — Assign an app role to the system user or select another app to continue" | step 3 skipped: the system user has no role on the app | close the dialog, **Assign assets → Apps → AutoResponseBot → Full control**, then generate again |
| AutoResponseBot is not in the **Apps** list in step 3 | the app is not in this business portfolio | **Accounts → Apps → Add** → connect app ID `847772258381375`, then step 3 |
| The WhatsApp account is not listed | the test account was created under another portfolio | tell the developer what the list shows; the account must be in the same portfolio as the app |

## 2. Connect the number in the dashboard

Dashboard → **Settings → Connections** → the WhatsApp card (owner only):

1. **WhatsApp Business Account ID** and **Phone number ID** from §1.2.
2. **Access token**: paste the system-user token (a password field; it is never shown again, never returned by the API).
3. **Connect number**.

What Connect does (`POST /api/whatsapp/connect`, `src/routes/whatsapp.ts`): checks the token with Meta (`debug_token`: issued to this app, both
WhatsApp scopes present), reads the number, subscribes this app to the WhatsApp account
(`POST /{waba_id}/subscribed_apps` — without that, Meta sends no events for the account), and stores the token
encrypted (AES-256-GCM, `src/config/crypto.ts`). A number already connected to another workspace is refused.

Then the card shows the number, a **test number** badge, status / quality / messaging-limit chips, and the free-replies
meter **n / 1,000 this month** with an estimated cost. **Refresh** re-reads health from Meta; **Disconnect** unsubscribes
the app, deletes the token and turns the agent off.

Connect errors and what they mean:

| Error | Meaning |
|---|---|
| `invalid_waba_id` / `invalid_phone_number_id` | not digits — copied the wrong field |
| `invalid_access_token` | the pasted value is not token-shaped (often a stray space or a paragraph) |
| `missing_scopes` | the token lacks `whatsapp_business_messaging` or `whatsapp_business_management` — regenerate (§1.4 step 4) |
| `token_refused` | expired, revoked, or issued to another app |
| `number_unreadable` | the token cannot see that phone number — the system user lacks the WhatsApp-account asset (§1.4 step 3) |
| `subscribe_failed` | Meta did not confirm `subscribed_apps` — retry; check the token has `whatsapp_business_management` |
| `number_in_use` | another workspace already holds this number |

## 3. The first test (agent still off)

1. Settings → Connections → WhatsApp card → **Who the assistant answers: Test senders only**, and add **your own phone** in international digits without `+`
   (e.g. `9665XXXXXXXX` or `2010XXXXXXXX`). The list also accepts WhatsApp user ids (`EG.…`) shown on a thread.
2. From that phone, message the test number.
3. **Expected**: the conversation appears in the **Inbox** within seconds, with your name and text; **no reply arrives**
   (nothing in this phase can send — `src/webhook/whatsappInbound.ts`), and the message carries the reason
   `no_reply_reason = 'agent_off'`.
4. A message from a phone that is **not** a test sender is stored as a bare record — no text, no name, no number — until
   the privacy pages mention WhatsApp. Its queued job copy is cut down the same way (`src/webhook/whatsappRedact.ts`).

Checks if nothing shows up, in order:

1. Is the WhatsApp account linked to the app? Connect does it; by hand: `POST /{waba_id}/subscribed_apps` with the token (2026-10-19: messages did not arrive until this was done).
2. Logs: `vercel logs msg-response-auto.vercel.app --since 30m | grep -E "POST /webhook|wa\."`
   - nothing at all → Meta is not sending: fields (§1.3 step 5) or `subscribed_apps` (Connect again)
   - `wa.no_creator` → the number is not connected in Settings (or connected in another workspace)
   - `wa.ignored` with `no_user_id` / `group` → expected for those messages
   - a 403 on `POST /webhook` → signature: the event came from a different Meta app (§1.1)
3. App subscriptions (read-only):
   `curl -s "https://graph.facebook.com/v26.0/847772258381375/subscriptions?access_token=847772258381375|$META_APP_SECRET"`
   must list `whatsapp_business_account` with the seven fields.

## 4. Going live on a real number (later)

The test number can only reach the recipients added in §1.2. A real number is needed before customers can write.
The number must be able to receive **one** SMS or voice call for verification and must **not** be active on WhatsApp.

| Path | Cost | Needs the SIM? | Keeps the number in the WhatsApp Business app? |
|---|---|---|---|
| **New SIM**, connected directly (the default) | price of a SIM | yes, once | n/a |
| **Replacement SIM** for the existing business number, moved to the API | carrier fee | yes, once | **no** — chats move to the dashboard; app history is not migrated |
| Existing number via **coexistence** (app + API on one number) | needs a Meta partner (e.g. YCloud's free plan — coexistence on that plan unconfirmed) | **no** — confirmed inside the app | yes |

Steps for a new number (direct): use case **Connect on WhatsApp → Step 2 → Register your WhatsApp phone number** → add the
number → receive the code by SMS or call → set a **6-digit PIN** (keep it; it is needed to re-register) → then Connect it in
Settings exactly as in §2 (the new phone number ID; the same token works if the system user has the account).

Before the agent may answer real customers (mode **Everyone**, which `PUT /api/whatsapp/agent` refuses with a 409 until then,
`src/routes/whatsapp.ts`): the privacy pages must name WhatsApp (PR #197, then #221), and the go-live checks (phase W10)
must pass.

## 5. Adding a managed customer's number (planned: phase W11)

Decided 2026-10-19: each customer brings a **new SIM that has never been on WhatsApp**. The number is registered in **your**
Meta business portfolio and linked to the customer's workspace; the customer only reads you one code, once.

What to tell the customer:

- a new SIM (any carrier), never used for WhatsApp, that can receive one SMS or call;
- keep the SIM, in a phone that stays on (Meta may ask to re-verify);
- their customers will see the **phone number, not the business name**, until display names can be approved (needs your
  business verification);
- WhatsApp costs beyond each number's 1,000 free replies a month are billed to your card and invoiced to them.

Limits while your business is unverified: **2 phone numbers in the portfolio in total**. Verification raises it to 20, so it
is the step to take before the second customer. The admin screen for this (add → code → PIN → assign to workspace) is task
group T063–T068 and is not built yet.

## 6. What works without business verification

- Unlimited replies to people who write first, inside the 24-hour window.
- Up to **250** people a day reached first by the business (templates) — not used in v1.
- Up to **2** registered numbers in the portfolio.
- No display name shown (customers see the number), no blue badge, no managed-client onboarding through Meta's own flow.

## 7. Costs and the rules the agent follows

| | |
|---|---|
| Incoming messages | free |
| Replies inside the 24 h window | first **1,000 per number per month free**; then ≈ **$0.0036** to Egypt, **$0.0107** to Saudi Arabia, each |
| Click-to-WhatsApp ad conversations | everything free for up to **7 days** after the business's first reply |
| Template (marketing) messages | ≈ $0.064 Egypt / $0.058 Saudi — not used in v1 |
| Typing indicator, read receipts | not billed — inferred (they are not messages; Meta's pricing page does not list them) |
| The app's guard | **Allow paid messages beyond the 1,000 free replies a month** on the WhatsApp card, **off** by default: past the free 1,000, sends are held, not billed |

Policy rules built into the agent: it stays on the business's own courses and support (Meta bans general-purpose AI
assistants), it says it is automated, a person is always reachable (it hands off on request), and WhatsApp messages only go
to AI providers that do not train on them (no free-tier Gemini).

## 8. Gotchas

- **The webhook check reads ONE workspace's verify token.** `GET /webhook` accepts `META_VERIFY_TOKEN` (env) or the verify
  token of the **first active workspace** it finds (`src/index.ts:339`, `LIMIT 1`). With several workspaces, the token you
  see in another workspace's Settings may not be the one checked. Use the **Default** workspace's token. Changing it in
  Settings does not break existing Instagram/Facebook subscriptions (Meta re-checks only when a subscription changes).
- **Fields empty = no events**, even with a green "verified" subscription (seen 2026-10-19 before §1.3 step 5).
- **The WhatsApp account must be subscribed to the app** (`POST /{waba_id}/subscribed_apps`); Connect does it.
- **Meta's "Check test webhooks" panel** (Step 1) shows payloads Meta generated; they did not reach our server on
  2026-10-19. Real messages from your phone are the test that counts.
- **A merge to `main` deploys production** (Vercel Git), so WhatsApp changes go live on merge.
- **Contacts may arrive without a phone number** (WhatsApp usernames): the thread is keyed by the WhatsApp user id
  (`EG.…`, `SA.…`), not the phone.
- **Inbound media is downloadable for 7 days only**; voice notes and images are saved by a later phase (W6).
- **Meta account model**: the WhatsApp Business Account is now split into a "WhatsApp account" (the number) and a
  "Messaging account" (templates, billing, webhooks). Existing IDs keep working; phone-number IDs in API paths are replaced
  in H1 2028 (handled in `src/services/whatsappConnections.ts`).
