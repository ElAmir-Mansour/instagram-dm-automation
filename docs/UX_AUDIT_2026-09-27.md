# AutoReply Pro — UI/UX audit and enhancement plan

**Date:** 2026-09-27 · **Branch:** `feat/monteur` @ 51b438a · **Scope:** the dashboard (18 page modules,
components, shell, CSS), the public pages, and the Arabic copy catalog.
**Method:** code audit with a `file:line` for every finding, the live site checked at
<https://msg-response-auto.vercel.app> (login, home, pricing; desktop and 375px), asset weights measured
with `curl`. Six focused reviews were run in parallel; every load-bearing claim below was re-checked
against the code before it was kept (the ones re-checked are marked ✓). Nothing was edited.

Effort: **S** under half a day · **M** one to two days · **L** more, or needs new backend data.
"backend" = the fix needs a server change. IDs are stable so the plan at the end can refer to them.

---

## 0. Executive summary

**The foundation is unusually strong.** RTL-first with logical properties only, WCAG-checked token pairs
with a CI guard, lazy page modules with hover prefetch, view-transition navigation with skeletons, focus
traps and dirty guards on modals, `aria-live` toasts, 44px tap targets, reduced-motion everywhere, honest
error panels with Retry, and a Studio that never loses typed work. None of that needs redoing. This audit
found no visual-design problem worth a redesign; it found **workflow and feedback gaps** on the screens
the operator uses every day, and a handful of **dead or misleading controls**.

**What matters most (twelve changes, all S or M):**

| # | Change | Why | IDs |
|---|---|---|---|
| 1 | Make every switch's visible text clickable (Posts, Studio, Campaigns) | Today only the 46px track toggles; the label is a dead span | P1, ST1 ✓ |
| 2 | Put the growth answer and the coach's first action on Overview | The morning screen answers "is the automation broken", not "what should I do" | O1, G1 |
| 3 | Give the Inbox a "needs reply" filter, a count, and remove the silent 20-thread cap | A customer from last month is unfindable; the waiting count is capped | I1, I2, I7 ✓ |
| 4 | Expose whole-word `match_mode` in the campaign form | It exists end to end in the backend; the form cannot set it | C1 ✓ |
| 5 | Accept the Arabic comma (،) as a keyword separator | Copying the placeholder saves one dead phrase keyword; the inspector calls it safe | C2 ✓ |
| 6 | Auto-refresh the Posts queue while rows are busy | "Publishing…" and "TikTok is processing" blink forever; no timer, no Refresh | P2 ✓ |
| 7 | Fix the three wrong confirmations (past time, red Publish-now, "Delete log") | Destructive-action safety is inverted: publishing is red, discarding an hour of Studio edits is silent | P5, P6, P7, ST2 ✓ |
| 8 | Show the token's real failure reason and the 90-day data-access expiry in Settings | Both are fetched and hidden | SE2, SE3 ✓ |

| 10 | Ship a favicon, manifest and theme-color; add the language toggle to the login screen | Blank tab icon, generic home-screen tile, English-only login on an English browser | SH1, SH2 ✓ |

**Weight worth cutting:** the first screen loads ≈300KB gzipped of JS/CSS before painting, of which
`i18n.js` is 85KB (both languages, every visit) and Lucide is 93KB from a CDN for 111 icons (SH5).

The plan in §8 sequences everything into three waves. Wave 1 is 25 S-sized fixes that touch copy, one-line
markup and confirmations; it is a single dashboard PR with one cache bump.

## 1. Cross-cutting findings (shell, IA, performance, a11y)

**SH1 · No favicon, manifest, apple-touch-icon or theme-color. S ✓**
`index.html` has none; `/favicon.ico` and `/manifest.json` are 404 on the live site. The tab shows a blank
icon and "Add to Home Screen" on an iPhone gives a generic tile — for a tool DESIGN.md says is opened
"at 8pm because someone commented". Fix: `/public/favicon.svg` + `apple-touch-icon.png` (180px), a
`manifest.webmanifest` with `display: standalone`, `theme-color` for both schemes. Also serve it on the
public pages (see §5).

**SH2 · The login screen has no language toggle. S ✓**
`index.html:94-131` — the toggle lives only in the app header (`:286`). First-visit language comes from the
browser (`:41-52`), so an Arabic operator on an English-locale device logs in through an English form with no
way to switch. Fix: render the same `lang-toggle` in `.login-card`, re-using `App.renderLanguageToggle`.

**SH3 · No unread/waiting signal anywhere outside the Inbox. S**
`grep unread dashboard/js` = 0; the inbox polls every 5s only while open (`inbox.js:29,174`); nothing sets
`document.title` or a nav count. The one thing the operator opens the app for (a customer waiting) is
invisible from every other screen. Fix: a count of "needs reply" threads on the Inbox nav item and in the
tab title, fed by the Overview's existing `/conversations` call (and see I7). Not decorative: it is data.

**SH4 · Four "numbers and logs" screens with overlapping content. M**
Overview, Analytics, Growth (with a second `?tab=seo` view) and Activity. Three tiles and one chart are
rendered on both Overview and Analytics from the same `GET /api/stats` (see the table in §2.5). Fix: Overview =
today and this week + briefing; Analytics = all-time and 30 days; delete the duplicates on the Overview side
(O4, O5, O6, A9).

**SH5 · First-load weight. M**
Measured gzip: tokens 5.5K · styles 46K · i18n **85K** · api 5.6K · components 16.5K · motion 7.3K ·
charts 7.8K · admin_common 10K · app 14.7K · overview 7.1K · Lucide UMD **93K** (CDN) ≈ 300KB before the
first screen. Fixes, in value order: (a) split `i18n.js` into `i18n.ar.js` / `i18n.en.js` and load the one
the inline snippet in `index.html:41-56` already decided on (−40KB); (b) replace Lucide UMD with an inline SVG
sprite of the 111 icons actually used (`grep data-lucide` across dashboard/ and public/), which also removes
the last CDN host from the CSP (−80KB and one third-party round trip); (c) keep the current lazy page modules.

**SH6 · Session expiry is silent on the login screen. S**
`api.js:72-78` clears the token and calls `App.showLogin()`, then throws `http.sessionExpired`; whether the
operator sees the message depends on the caller toasting it. Fix: `showLogin(reason)` renders the reason into
`#login-error` so the bounce is explained; keep the hash so re-login lands on the same page (already does).

**SH7 · Breakpoint drift. S ✓**
The inbox goes single-pane at ≤900px (`styles.css:2491`), the drawer at ≤860 (`:2508`), forms at 900,
toolbars/modals at 768, tiles at 560/400. Between 861 and 900px the desktop sidebar is open and the inbox
is one pane. Fix: align on 860 (the drawer) and 768 (density); tokenise them as comments since CSS cannot.

**SH8 · Errors by toast while a modal has focus (pattern). S**
Campaign create/edit (`campaigns.js:659,683`), users set-password (`users.js:627`), tenants create: the
server's English message lands in a corner toast while the modal keeps focus and no field is marked.
`UI.errorStrip` and `UI.markInvalid` exist (`components.js:765,385`) and Posts already does this right
(`posts.js:3256-3277`). Fix: an error host at the top of every modal form.

**SH9 · Whitespace-only submits do nothing, silently (pattern). S**
`settings.js:804,829`, `tenants.js:332`: `if (!value.trim()) return;` after the browser's `required` passed
on spaces. Fix: `UI.markInvalid` + `errorStrip`.

**SH10 · No desktop sidebar collapse. L (skip)**
268px fixed (`tokens.css:89`). Fine at ≥1100; tight at 900–1100 with Studio or the Growth table. Not worth
the work now; noted so it is not rediscovered.

**Already done well (shell):** RTL default with logical properties (149, zero physical), contrast guard
over the composited glass stack, view transitions with page skeletons, hover/focus prefetch of page modules,
`aria-current` on nav, focus trap + dirty guard + Escape on modals, `aria-live` toasts that pause on hover,
drawer with scrim/Escape/focus return, setup mode for a fresh deployment, `Admin.confirm` for destructive
actions, error panels with Retry, SVG charts with sr-only tables, no webfont, theme applied before first paint.
